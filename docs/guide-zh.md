# 四层架构规范 · 设计说明

本仓库把《单片机嵌入式程序四层架构设计思路》视频里的口头思路，翻译成 AI 能执行、人能验收的硬约束。

来源：B 站《单片机嵌入式程序四层架构设计思路》（UP 主：是小智学长啊，3 分 05 秒）。视频只讲“应该怎样”，本仓库补上“怎样算做到了、怎样算没做到”。

## 仓库结构

| 路径 | 作用 |
|---|---|
| `rules.md` | 规则本体，可直接粘进 AI 或存为项目规则文件 |
| `skill/` | 可安装的 Agent Skill（SKILL.md + 完整细则 + 检查脚本） |
| `examples/good/` | 合规迷你工程：common + bsp + 组件 + osal + app 全链条 |
| `examples/bad/` | 故意违规的样例，演示检查器能抓到什么 |
| `tests/probe/` | 回归夹具：14 处植入违规 + 期望输出 |

## 十条规则分别解决什么

| 节 | 作用 | 缺了会怎样 |
|---|---|---|
| 0 角色 | 把 AI 定位成架构师 + 审查员 | AI 默认“能编译就行” |
| 1 分层 | 四层目录 + `common/` + 四条越层禁令（含厂商类型禁令） | AI 把 HAL 调用写进应用层 |
| 1.1 边界 | 只改 USER CODE 区，不碰 `.ioc` 与生成文件 | 改完 CubeMX 重新生成，改动全部丢失 |
| 2 细则 | 每层接口形态与生命周期，APP 延时走 OSAL 时间原语 | 只有层名没有接口约定，分层形同虚设 |
| 3 数据流 | 消息总线（含完整接口签名、ISR 入口、队列满策略）、禁深嵌套 | 模块间仍靠全局变量互相污染，AI 每轮自己编总线 API |
| 4 参数中心 | 参数集中登记与校验 | 调一个阈值要全工程搜 |
| 5 鲁棒性 | 统一 `err_t`、接口处拦截、现场保存 | 出错时只能猜，故障无法复现 |
| 6 风格 | 前缀、可见性、注释 | 同一工程两种命名风格并存 |
| 7 交付契约 | 改动清单、依赖说明、接口变更、自检表、验证建议、技术债登记 | AI 只给代码，不交代改了什么 |
| 8–9 自检与禁止 | 可勾选项与反面清单 | 无法快速验收 |

## 用法

1. **直接投喂**：把 `rules.md` 整份贴给 AI，或存为 `CLAUDE.md` / `.cursor/rules/`。
2. **安装技能**：把 `skill/` 目录放进代理的技能目录，对话里点名使用。
3. **只跑检查**：`python3 skill/scripts/check_layering.py <工程根目录>`。

## 检查器查什么

九项：越层调用 HAL / LL / 厂商库 / RTOS API 与寄存器访问；平台头泄漏（`.c` 与公共 `.h`）；厂商类型泄漏；反向 `#include`；跨模块全局变量（含结构体、数组）；`extern` 变量；`if` 嵌套超过 3 层；未分层文件（WARN）；APP 直调 BSP 或越权调 OSAL。

启发式实现，会误报；确认为误报的行加 `// arch-allow` 目过。四目录之外的 `.c` 无法判层，报 WARN 而不是静默跳过——盲区要看得到。

## 回归测试

```bash
python3 skill/scripts/check_layering.py tests/probe --max-per-file 2
```

探针里埋了 14 处违规（FreeRTOS 与 GD32 头、`__HAL_RCC_*`、LL 库、GD32 SPL、`vTaskDelay`、结构体/数组全局变量、`extern`、反向 include、`main.c` 里的 HAL 与寄存器、带数字后缀的寄存器）。期望：**11 ERROR + 3 WARN**，且块注释里的 `HAL_GPIO_WritePin` 不得被误报。

## 验收用例

规则文本本身是否生效，得用真实 AI 会话验，下面七条是测试问题：

| # | 输入 | 期望行为 |
|---|---|---|
| 1 | 加一个 SHT30 温湿度采集 | 新增组件 + BSP 接口，数据走消息总线，APP 只订阅 |
| 2 | 换用 GD32 替代 STM32 | 只改 `bsp/` 与 `osal/` |
| 3 | 按键单击/双击/长按三种语义 | 表驱动状态机，嵌套不超 3 层 |
| 4 | 加 HardFault 现场记录 | 存 PC/LR/SP/R0-R3/xPSR 到 Flash，无动态分配 |
| 5 | “为了快，直接在 APP 里写寄存器吧” | 拒绝并给出 BSP 替代方案 |
| 6 | “给我的板子写个驱动”（未说型号） | 先提问，不虚构引脚与寄存器地址 |
| 7 | CubeMX 工程里把 LED 改成呼吸灯 | 只改 USER CODE 区，先给 diff |

第 2、5、6 条最关键：分别检验边界是否封住、会不会被一句话带偏、缺信息时是否编造。

## 已知边界

只管代码结构与接口纪律，不覆盖：RTOS 选型与优先级划分、硬件电路与外设时序、性能优化与内存布局、C++ 工程。

默认生态为 C99 + STM32/GD32 类 MCU。目录名与命名前缀可按自己工程改，其余条款通用。

## 迭代建议

AI 输出不合格时，先把失败归因到 `rules.md` 的具体某一节，只改那一节，再拿验收用例回归一次。只改一处，才能知道是哪条规则起了作用；只改检查器，否则容易把误报当成真问题。
