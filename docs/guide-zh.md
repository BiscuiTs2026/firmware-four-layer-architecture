# 设计说明与取舍

这个仓库起源于“AI 写固件总是烂在同一个地方”这个观察，后来在真实工程上做了两轮校准。本文说明每个取舍的理由，以及不这么做会怎样。

## 为什么保留四层，而不是更少或更多

三层（硬件 / 逻辑 / 应用）在裸机上够用，但一旦同时存在“换芯片”和“换 RTOS”两种变化，缺一层就会把两者耦在一起。四层里 OSAL 是唯一为“将来可能上 RTOS”预留的层；裸机工程里它可以只实现时基与延时，成本约 40 行。

五层以上没有额外收益：MCU 工程的外设种类有限，再分只会增加跨层跳转次数。

## 为什么要单独承认“入口胶水层”

v1 把入口也当成 APP 层来约束，结果检查器在一个裸机工程上刷出 48 条 ERROR，其中一半是 `main.c` 里不可避免的寄存器初始化与 `SysTick_Handler`。
规范如果要求做不到的事，执行者只会加豁免，最后规则形同虚设。

v2 的处理：给入口一个显式身份 `glue`，允许碰寄存器与 HAL，但用两个硬指标限死它——**只做初始化与中断分发**、**≤ 200 行代码**。
这样“巨型 main.c”仍然会被抓（268 行的工程照样报错），而正常的 97 行入口不再产生噪音。

## 为什么不再强制“跨模块只走消息总线”

v1 要求所有跨模块数据都走统一消息结构。这在 RTOS 工程里成立，在裸机小工程里会带来三个成本：

1. 为一条 3 字段的遥测帧引入队列、订阅表、消息 ID 分段；
2. 20 Hz 的节拍下，总线反而成为新的时序风险点；
3. 调试时多一层间接，SWD 直接看变量更有效。

v2 的口径：**跨模块“写”必须走参数中心或明确的 API；跨模块“读”允许只读快照**。
这条改动让规范在 6 KB 级工程上从“必须重构”变成“可以逐步下沉”。

## 为什么保留固定地址快照，还给它写规矩

用 SWD 按固定地址回读运行态，是这个工程族最有效的排障手段，比串口打印快得多。禁止它等于让人放弃最好的工具。

但它出过事故：链接脚本里一个 `.fixed_ram*` 通配把后加的段一起吞进同一地址，两个结构体互相覆盖，读出来的全是脏值。
所以 v2 把“怎么放”写成显式约定：段名唯一、地址显式、禁止通配、首字段 `magic`、字段偏移注释、区间不得重叠。
检查器能抓同址、未在 `.ld` 显式定义、固定段内通配，以及声明长度后的区间重叠；其余（例如未标长度的跨地址重叠）靠评审。

## 为什么“if 嵌套 ≤ 3 层”保留但标注为误报源

这一项在真实代码上的误报率最高：字模渲染（`for → for → if → if`）与 `switch` 状态机都会被算成深层嵌套。
保留它的理由：它抓的是真正的“金字塔式判空 + 业务分支”，这类代码确实是缺陷温床。
处理办法是明确标注误报场景并允许 `arch-allow`，而不是删掉规则——删掉之后，复杂分支会肆无忌惮地长回去。

## 为什么检查器要有“角色清单”模式

实测最刺眼的一条：不写清单直接扫一个 3569 行工程，结果是 **0 ERROR**。
因为检查器只约束 `app/ bsp/ osal/ components/` 里的文件，扁平 `src/` 全部被跳过。绿灯是假的。
现在这条已堵上：没有分层目录也没有角色清单时直接返回 1，必须显式 `--allow-unlayered` 才会放行。

角色清单解决了“不移动文件也能检查”的矛盾：只要声明“谁是谁”。
代价是清单会过时；清单里出现已删除的文件时检查器不报错，这一点靠 code review 兜。

## 为什么不做成编译器的静态分析

- 各厂商 SDK 的构建系统差异太大，做成 lint 插件反而绑定 CubeMX 或 CMake；
- 需要约束的是结构（谁调谁、变量放哪），这些用正则 + 花括号深度足够；
- 纯 Python 单文件、零依赖，任何人 `python3 check_layering.py .` 就能跑，接 CI 成本最低。

## 验收方式

改规则或改检查器后，必须让下面的命令全绿：

```bash
python3 tests/run_tests.py
```

夹具覆盖 59 条植入违规（目录模式 26 条 + 对抗夹具 13 条 + 清单模式 4 条 + 违规样例 16 条），
并包含一段“注释里写着违规代码”的反例，确保注释屏蔽没有退化。

此外建议在一个真实工程上跑一次，人工核对每条 ERROR 是否成立。实测数据见 [measurements.md](measurements.md)。

## 与 v1 的差异

| 项 | v1 | v2 |
|---|---|---|
| 入口层 | 归入 APP，与业务同待遇 | 独立 `glue` 角色，≤ 200 行 |
| 跨模块数据 | 强制消息总线 | 写走参数中心/API，读可用只读快照 |
| 扁平工程 | 完全不检查 | 角色清单 `.arch-roles` |
| ISR | 文字约束 | 可机检（阻塞/格式化/动态内存） |
| 固定地址段 | 未涉及 | 显式约定 + 同址/重叠/通配检查 |
| 时序 | 未涉及 | 采样节拍、循环耗时上限、分块非阻塞 |
| 上板流程 | 未涉及 | 分批汇报、串口独占、烧录前说明 |
| 检查器误报 | `SystemCoreClock` 等 | 默认豁免 + `arch-allow:snapshot` |
